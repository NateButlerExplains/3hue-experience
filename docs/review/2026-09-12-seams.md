# 3. The routing contract

**Arrival stores four values, not five.** `arrive-question`'s option ids are `prove`, `own`, `run`, `browse`. The chapter is explicit: *"Four buttons, not five… `early` is stored once, in the lobby."*

**The lobby does not store `early`.** The lobby chapter's choice is `id: segment`, `remember: "segment"`, with four options → `wt` / `gc` / `sr` / `all-wt`. There is no `situation` key on it and no option storing `early`. The lobby chapter says so on purpose: *"Choice id `segment` and `remember: 'segment'` deliberately unchanged."*

**So `situation = early` is never stored anywhere in the tour.** `check-manifest.js:632-633` is unambiguous:

```js
if (!remember.has(k)) { err(p, `answers.${k}: no choice remembers ${k}`); continue; }
for (const x of [].concat(vals)) if (!remember.get(k).has(String(x))) err(p, `answers.${k}: no option stores ${JSON.stringify(x)}`);
```

Every one of these is a hard lint error and a permanently silent line:

| Line | Chapter | Condition |
|---|---|---|
| `lobby-early` | Lobby | `situation = early` |
| lobby choice, the "no Suggested tag" branch | Lobby | depends on `early` existing |
| `start-notyet` | Path | `situation = early` |
| `sum-early` | Close | `situation = early` |
| `sum-situation` | Close | value list includes `early` |

**Who reads `situation` today:** `lobby-yours-prove/own/run`, `lobby-browse`, `lobby-early`, the four `suggest` clauses on the lobby choice, `baseline-3`, `review-any`, `start-notyet`, `sum-situation`, `sum-early`. That is it — all in Lobby, Path and Close.

**Who should read it and does not.** The Arrival chapter issues a direct instruction the three door chapters ignored:

> "`wt-1`, `gc-1`, `sr-1` — rebuild. All three currently open by describing a company type and will contradict the answer the visitor just gave. Each should confirm the ask, with a variant gated on `{answers: {situation: ["prove"]}}` / `["own"]` / `["run"]` and an ungated default."

- `wt-1` — `always`, no variant.
- `gc-1` — `always`, no variant.
- `sr` opens on `sr-2` and `sr-holds` — both `always`, no variant.

A visitor who answers "They want a report or a certificate" is dropped straight into Win Trust and hears "This room holds two things: how you run security, and what your scope covers." Nothing acknowledges the answer they just gave. Same for the other two. Since these three nodes are also the *only* place most visitors land after arrival (see 2a), the arrival question currently changes nothing a visitor can hear except the door they end up in.

**Also not reading it where the Path chapter said it must:** the Path chapter's own "Still open" says *"the summary needs a line of its own gated on `situation = browse`… and `close-1` needs a gate."* Close instead gated `close-1` on triggers and `close-1-all` on `segment = all`. So the two chapters use two different keys for the same visitor.

**Do `browse` and `early` share a value?** No — but only because `early` has no value at all. Once `early` is given a home, confirm they stay distinct; the lobby chapter's own text depends on it (`lobby-browse` and `lobby-early` say opposite things about whether a door is theirs).

**One more:** `sum-situation` prints `{answer:situation}` verbatim. The four labels are the arrival buttons. Three read as sentences; the fourth does not:

> "What brought you in: I'd rather see all three"

That is not what brought them in.

# 4. The everything route

Walking `lobby → all-wt → all-gc → all-sr → path-all → close`:

**Does it end with a real named first step?** **Yes.** `all-wt-4` names `{offer:initial-risk-assessment}` in the first room, `path-all-start` names it again at the tower, and `sum-all-start` carries it into the email. Three chapters independently landed on the same offer. That part works.

**Does the summary claim a door they never chose?** **No.** I traced it. `sum-wt`, `sum-gc` and `sum-sr` all print — but they print only `{door:X.title}: {door:X.promise}`, which is honest for someone who walked all three. None of `sum-wt-deal`, `sum-wt-evidence`, `sum-gc-*` or `sum-sr-*` fires, because each needs a `trigger-*` answer and the everything route stores none. `close-1` ("That's your door") is correctly gated off; `close-1-all` fires instead. `close-3-all` fires. Ten lines, as Close claims. Verified against `js/tour.js:449` (`st.answers.door = d`), which does set `door = stay-ready` for this visitor — but nothing on this route reads `answers.door`, so the stale value never surfaces.

**The route breaks somewhere else, and badly.**

Stay Ready added a choice at the end of `all-sr`:

> **Choice** — "Three doors walked. Which one is yours?" (id `all-sr-start`, remembers `start-all`): "{door:win-trust.title}" … "{door:gain-control.title}" … "{door:stay-ready.title}" … "Not sure yet"

**Nothing reads `start-all`.** Not `path-all`, not `close`, not the summary. All four options go to the same node. Stay Ready flagged the dependency in its own "Still open" — *"`path-all`, the tower's start nodes and the summary must read `start-all`"* — and neither Path nor Close did it.

The consequence is one node later. A visitor picks **Win Trust**, walks through the doorway into the tower, and the seventh line is:

> `path-all-start`: "**You didn't pick a door, and you don't have to.** Without one, the first step is usually the {offer:initial-risk-assessment}."

Then `close-1-all`: "You've seen all three. **All three begin in the same place**." Then `sum-all-start`: "the same first step **behind all three doors**."

Three lines in a row deny a choice the visitor made ten seconds earlier. This is the sharpest single defect in the script. Either `all-sr-start` is cut, or `path-all-start`, `close-1-all` and `sum-all-start` gain `start-all` branches.

**Secondary:** on this route, `wt-panel-4` still carries the four readiness packages (written at `all-wt-3`, never cleared) while `all-wt-4` says the first step is the Initial Risk Assessment. `check-manifest.js:443` forbids exactly that pairing in a `starts` object — *"no standalone Initial Risk Assessment beside SOC 2 Readiness or ISO 27001 Certification Readiness, which carry one"* — and the lint will not catch it here because it is a write, not a start. The visitor sees the prohibited combination on the glass.

# 10. Ear test — the five worst lines to say aloud

**1. `sr-p1` (and, identically, `ask-exam-3` and `ask-proof-3`) — 25 words, one breath, three institutional noun-stacks.**

> "Engagements are scoped and delivered by the same practitioner, whose background includes closing FDA 483 observations and remediating bank Matters Requiring Attention under sustained examination."

Nobody can say "remediating bank Matters Requiring Attention under sustained examination" out loud without slowing to a crawl, and it lands three times in one tour. Shorter:

> "The same practitioner scopes the work and delivers it. He has closed FDA findings and bank examiner findings while the exam was still running."

Note: this is a `ref` to `doors.stay-ready.proof[0]`, status `approved-copy`, so it can only change in the manifest, with the owner's sign-off.

**2. `sr-ch-2` — decimal percentages, spoken.**

> "86.8% of small businesses have deployed MFA, but only 51.1% require it across all key accounts."

"Eighty-six point eight percent" is not a sentence a person says. Shorter:

> "Most small businesses have switched MFA on. Only about half require it everywhere."

(The precise figures survive on the `card` write and the callout, where they are read, not heard.)

**3. `wt-ch-4` — two statistics welded with "while".**

> "68% of companies have one or fewer full-time security people, while 93% call security a top priority."

Shorter, and it keeps the sting:

> "Almost every company calls security a top priority. Most have one security person, or none."

**4. `wt-scope-r2` — an eight-word product name at the end of the breath.**

> "If the auditor wants the system itself described, that's {offer:system-security-privacy-plan-sspp-development}."

Renders as "…that's System Security & Privacy Plan (SSPP) Development." Give the ear a landing before the name:

> "If the auditor wants the system described, there's a document for that: {offer:system-security-privacy-plan-sspp-development}."

**5. `sr-inc-r1` — a four-item list after a colon, ending on a phrase the room contradicts two lines later.**

> "The start is {offer:ir-fast-start}: a response plan, playbooks, a tabletop exercise and standing incident command."

Shorter, and it stops colliding with `sr-inc-live`:

> "The start is {offer:ir-fast-start}: a plan, playbooks, and a rehearsal before you need one."

**Runners-up, in order:** `ask-prepare-1` (26 words, four-item list); `ask-msp-1` (26 words, three-part question inside one sentence); `gc-ven-r3` ("Before that, {offer:asset-governance-program-development}." — a five-word product name as a standalone fragment); `sum-what` (29 words, but it is read, not spoken).
